## Long-term data behavior
- **Refresh policy**: No scheduled refresh; all data is user-generated through the app's own forms and read live from the artifact database on every open.
- **Growth**: Bookings, professionals, customers, reviews, complaints, notifications and admin logs grow only through real in-app submissions. The 12 service categories and 12 Tangail upazilas from the prompt are seeded once as platform reference data (admin can rename/reprice/enable-disable afterwards); no demo professionals, ratings, reviews or bookings are seeded — professionals appear only after real registration + admin approval, reviews only after real completed jobs.
- **Ordering**: Bookings newest-first in every panel; professionals sorted by real average rating then completed-job count (both computed from stored reviews/bookings, never stored as editable numbers).
- **Time semantics**: Booking preferred date/time are stored as the customer entered them (Asia/Dhaka wall time, shown verbatim); created/updated timestamps are instants rendered viewer-local.
- **Auth note**: Accounts are phone + password records created in-app (passwords stored hashed server-side); admin access is granted only to the account the owner promotes — role is checked in every privileged server action.
